# 승인 게이트 정책 (2026-09-21)

> 코드: `server/lib/gatePolicy.js` (정책·검수) · `scripts/gate-eval.js` (CLI) · `GET /api/gate-eligibility`, `GET /api/mcp/gate-eligibility`
> 검수는 **결정론적 코드**(파일 읽기 + ffprobe/ffmpeg)로만 하며 AI 호출이 없다(토큰 0). 검수기는 **판정만** 내고 승인은 하지 않는다.

## 1. 승인이란
- `gpoints` 의 `g1~g5` = **"이 산출물을 다음 단계 입력으로 써도 된다"는 확정 신호**다. 파일이 있다고 승인된 것이 아니다.
- 생성 여부는 파일 존재로, 승인 여부는 gpoints 로 따로 본다(이중 진실 금지). 생성 이벤트가 승인을 대신 찍으면 안 된다(2026-09-01 G3 오염 사례).
- G4 승인은 G5(편집 합성) 자동 실행의 조건이다 — 전체 컷 G4 승인 시 리더가 G5 를 시작한다. 따라서 G4 승인은 "이 영상이 최종 조립에 들어가도 된다"는 뜻이다.

## 2. 판정(verdict)
| 판정 | 의미 | 다음 행동 |
|---|---|---|
| `approved` | 이미 승인됨 | — |
| `not_ready` | 산출물 없음 | 제작·업로드·합성부터 |
| `blocked` | 하드 검사 실패 | **승인 금지**, 사유를 고친 뒤 재검수 |
| `recommend` | 하드 통과, 사람 확인 필요(정책상 사람 전용 / 소프트 경고 / 수동 확인 항목) | 사람이 1클릭 승인 |
| `auto_ok` | 하드·소프트 전부 통과 + 정책상 위임 가능 | 리더가 **위임받았을 때만** 자동 승인 가능, 아니면 사람 1클릭 |

검사 수준: **hard**(필수) · **soft**(경고, 있으면 `auto_ok` 불가) · **manual**(사람 판단, 있으면 `auto_ok` 불가).

## 3. 게이트별 기준
| 게이트 | 승인 대상 | 하드 검사 | 소프트/수동 | 위임 |
|---|---|---|---|---|
| **G1 대본** | 컷 대본 | DU>0, CT 지정, (메이킹 외) 프롬프트 존재, 세그 길이가 4/6/8/10초 | 세그 합계−DU 가 0~4초, 서여리 컷은 DL/NR | ❌ 사람만(창작 판단) |
| **G2 이미지** | 선택본 1장 | 이미지 존재, `selectedImage` 지정 | 얼굴 일관성·신발·배경 인물(수동) | ❌ 사람만(시각 판단, 비전 QC P4 전까지) |
| **G3 음성** | 컷 TTS 음성 | 대사/나레이션 있는 컷만 대상. 파일 정상·길이>0.3초, **길이 ≤ DU+0.5초**, **무음 아님(평균 −45dB 초과)** | 클리핑(최대 −0.3dB 미만), TTS 이후 대본 불변 | ✅ 위임 가능 |
| **G4 영상** | 컷 최종 영상(`cut_NN.mp4`/`_final`) | 파일 정상(비디오 스트림), **화면 비율**(LF/SF 16:9, 그 외 9:16), **길이 ±1초(DU)**, 모든 세그 슬롯 채움, 반려 없음, 대사 컷은 **오디오 스트림 + 무음 아님** | 검정 화면 <30%, 서여리 컷 연기·립싱크·얼굴(수동) | 메이킹 컷(GRAPHIC/BROLL/CAPCUT)만 ✅, **서여리(YEORI) 컷은 ❌ 사람 1클릭** |
| **G5 편집** | 최종 편집본 | (검수 미구현) | — | ❌ 사람만 |

## 4. 에이전트 리더 위임 규칙
1. **기본은 전부 사람.** Notion 에피소드 파이프라인 DB "에이전트 자동승인"이 비어 있으면 리더는 승인 대기 로그만 남긴다.
2. 위임은 **스테이지 하나씩**(`G3`, `making`). 위임해도 `auto_ok` 판정인 컷만 승인한다 — G1·G2·G5 와 서여리 컷 G4 는 위임해도 자동 승인되지 않는다.
3. **사람이 항상 이긴다**: 반려된 컷·사람이 승인 취소한 컷은 재승인하지 않는다. "보류" 체크 시 그 사이클은 아무것도 승인하지 않는다.
4. **fail-closed**: 검수기 호출이 실패하면 승인하지 않고 로그를 남긴다.
5. **기록**: 자동 승인은 에이전트 리더 로그 DB 에 `자동승인`(근거 포함), 검수 실패는 `블로커`(사람 개입=TRUE)로 남는다.
6. 위임 순서 권장: `making`(G4 메이킹 컷) → `G3` → (후속) 서여리 컷 G4 는 비전·STT QC 도입 후 재검토.

## 5. 사람의 승인 처리 절차
1. 현황 확인: `node scripts/gate-eval.js G4` (또는 `all`). 허브 상태 블록의 "승인 현황" 줄에도 나온다.
2. `blocked` → 사유(길이 불일치·오디오 없음 등)를 고친 뒤 재검수. 특히 **최종 영상(`cut_NN.mp4`)이 오래된 파일**이면 "클립 합성"부터 다시.
3. `recommend` → 영상을 보고(서여리 컷은 립싱크·연기 확인) 스튜디오 영상 탭 "G4 승인" 또는 MCP `studio_approve_g4`(컷 지정)로 승인.
4. `auto_ok` → 위임 중이면 리더가 처리, 아니면 사람이 일괄 승인해도 된다.

## 6. 적용 예 — LF_T01 (2026-09-21 검수)
- G4: 승인 1 · 승인 권고(`recommend`) 13 · 위임 가능(`auto_ok`) 4(BROLL 컷) · **막힘 3** · 산출물 없음 2.
- 막힌 컷 예: 컷 14(최종 영상이 9/9 옛 파일 10초·오디오 없음 — 3클립 24초 합성 필요), 컷 10·15(GRAPHIC 영상 길이가 DU 와 불일치).
- G3: 승인 13 · 위임 가능 2 · 해당 없음 8. G2: 승인 16 · 산출물 없음 7.

## 7. 후속(P4)
- 프레임 QC(정지·검정·얼굴 identity, 비전) · STT 대사 일치율로 립싱크 자동 점검(비용 있음, opt-in) → 서여리 컷 G4 위임 재검토.
- 승인 주체 기록(`approvedBy: human|leader`, 시각) — 현재 gpoints 는 승인 여부와 시각만 저장.
- 영상 탭 "검수 통과 컷 일괄 승인" 버튼(현재는 CLI/MCP).
